## 原因 1（主因）：指纹理解反了半截

TUT 事件前 Gate 同时出现两件看起来矛盾的事：

- 按**账户数**：散户一边倒空（`lsr_account≈0.26`，空头用户 3000+ vs 多头 900）
- 按**持仓量**：大户是净多的（`top_lsr_size≈1.7`），而且多头人均仓位是空头人均的几十倍（控盘度 C≈35）

Claude 把它收成三个必须**同时**高的量，再取几何平均：

- **D** = `top_lsr_size / lsr_account`（大户按量偏多 / 散户按户偏空）
- **C** = 大户人均多仓 / 人均空仓  
- **K** = 空头人数 / 多头人数  

`操纵结构分 = (sD·sC·sK)^(1/3)` —— 三个里有一个不高，整项接近 0。这就是「庄家吸空」和「市场真看空」的分界。

我们用的是：

- 空头账户占比高 → 加分  
- `top_lsr_account` 低（大户**账户**也偏空）→ 再加分  

等于把「大户也在空」当成更危险。TUT 的真实结构是 **大户用仓位做多、散户用账户做空**。我们缺 D、缺 C，几何门也没设，于是：

- 龙虾这种「结构脏了好几周、燃料没堆满」会反复报警（我们 28 次、命中率 50%；他们规则 A **根本没报**，峰值 SSRI 才 52.8）
- BEL、EPIC 长期挤着，12 小时冷却一次，次数被放大（EPIC 我们 49 次，他们 A 只记 1 个 episode）

规则 D 更狠：`空头浮亏 U>40%` **并且** `三日 OI 增到 3 倍`。U 是用近 3 日 ΔOI>0 的标记价做 VWAP，现价相对这笔「新空成本」已经浮亏 40%——空头燃料已经点着了。我们只有 24h OI 涨幅，没有这笔成本价，所以报不出「马上要爆」，只能报「仓很挤」。

---

## 原因 2：计数方式让分母膨胀

同一段危险期：

- 他们：48 小时并成 **1 次**；若是轧空后的余波，直接踢出样本  
- 我们：12 小时又能算 **1 次**；轧空后 SFI 还高，继续算误报/命中  

龙虾 6–7 月一直空头拥挤，7 天里经常走不出 +50%。他们把这类记到规则 B，并写明「结构只能说随时可能爆，不能说何时爆」。我们把同类信号放进唯一的「强警报」，精确率就被拖到 35%。

OI 门槛 $100 万 vs $200 万，还会多放进 MAGMA / SWARMS / XPD / SPX500 这种小盘噪声。

---

## 原因 3：A/D 天生更「挑」

规则 A 半年只响 **17 次**，名单基本就是 RAVE / STO / TUT / BICO / BANK… 那些已经发生的暴力轧空。  
规则 D 月均约 8 次，召回比 A 高，但仍要求「价格已远离新空成本 + OI 三天翻倍」——很多时候盘面已经在磨涨。

精确率 93–94% 的代价是：漏掉「对着均衡持仓硬拉」的 TAC / 西兰花，以及大量 50–100% 的轮动。他们自己也写了：50–100% 的事件 A∪D 只覆盖约 8%。

我们 143 次、35%：更像「空头拥挤雷达」，报得多、杂、早，和他们规则 C（空头占比>60% 持续 4h，精确率约 42%）是一类东西。

---

## 结论（对你风控怎么用）

两边命中判定差不多，**不是我们打分更严所以显得差**，是：

1. 我们没抓住 TUT 的核心结构（D/C 撕裂 + 多头仓位集中），指标更像规则 B/C；  
2. 冷却短、不并 episode、不剔除余波，同一段危险被数了很多次；  
3. 他们 A/D 是窄而准的对冲扳机，我们是宽的拥挤过滤器。

若目标是「少报、报了就要减空」，应以他们的 **A（SSRI）和 D（U+F）** 作红色信号，我们的 SFI 最多当橙色「禁加空」。数据已经在 `data/cache/` 里，不必重新限流去拉；若要，我可以把 D/C/U/F 接到现有缓存上，按他们的 A/D 在同一套 Gate 全量数据上复算一版精确率，两边才能用同一分母对比。
