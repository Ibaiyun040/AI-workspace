## 该租什么

| 场景 | 建议 | 别租 |
|---|---|---|

## 为什么「换节点」有时有用、有时没用

Gate 公网接口是按 **出口 IP** 限流（大约 200 次 / 10 秒 / IP），不是按你电脑网卡。

| 做法 | 效果 |
|---|---|
| 日常只用一个香港节点 | 还是 1 个 IP，8 线程也共用这一桶额度 |
| 扫一会儿手动换一个节点 | 换完额度重置，但仍是串行一个 IP |
| Clash 里做 **load-balance**，多条不同出口 | 真正并行，N 个 IP ≈ N 倍额度 |
| 同一机场「香港 01/02/03」 | 经常同一机房、同一 /24，Gate 可能仍当成一家 |

所以：**能规避的是「单一出口」的限流，规避不了机场共用 IP 池。** 要挑不同地区、最好不同家的节点（港/新/日/台各几条），测一下出口 IP 别撞车。

## 推荐做法（只让 Gate 走负载，别动你上网）

在 Clash 配置里加一个只给交易所 API 用的组，不要把 GLOBAL 切成负载，否则浏览器也会乱跳。

```yaml
proxy-groups:
  - name: GateLB
    type: load-balance
    strategy: round-robin   # 或 consistent-hashing
    url: https://www.gstatic.com/generate_204
    interval: 300
    proxies:
      - 香港A
      - 新加坡A
      - 日本A
      - 台湾A
      - 香港B   # 确认和香港A不是同一个 IP

rules:
  - DOMAIN-SUFFIX,gateio.ws,GateLB
  - DOMAIN-SUFFIX,gate.com,GateLB
  - DOMAIN-SUFFIX,bitget.com,GateLB
  - DOMAIN-SUFFIX,bybit.com,GateLB
```

8 个拉数线程打 `api.gateio.ws` 时，Clash 会把连接分到不同节点。每个出口自己有一份 200/10s，理论上接近线性加速。

## 不要指望脚本自动切节点（除非你先开控制口）

你现在 Verge 里 **`enable_external_controller: false`**，脚本没法列出/切换节点。若要让回测自动换节点，需要：

1. Verge 设置里打开 External Controller  
2. 再写「429 就切下一条」的逻辑  

即便开了，**一次只能切当前选中节点**，全局流量会跟着跳，不如 load-balance 干净。

## 和「去租机器」怎么选

- 本机 + Clash 负载组：零成本，先试 6～8 条不同出口，往往够把 907 个合约压到十几分钟。  
- 仍慢或机场 IP 重复：再租 **香港/新加坡 4C8G**，比租 GPU 有用。  
- 不要为这件事租 4090。

全量扫描还在本机 8 线程跑（已走你当前这一个 Clash 出口）。若你加上面的 `GateLB` 并重载配置，**不用停脚本**，新连接会自动分流。需要的话我可以在拉数层再加「429 自动降并发 / 换组」的保护。

## 不再受限流的

只要时间范围、粒度、接口和第一次拉的一样：

- 改 SFI 阈值、加减特征权重  
- 改命中规则（50% / 振幅 / 空爆、窗口 24h 还是 7 天）  
- 换冷却时间、只统计某类币  
- 同一套 OI / K 线 / 多空 / 清算上做分段、参数扫描  

这些都是纯本地计算。第二次跑 `year-gate` 时，已缓存的币基本是读盘 + 算分，瓶颈变成磁盘和 CPU，不是 200 次/10 秒。

指标本身也是无 I/O 纯函数：`extract_features` → `evaluate_indicator`，和拉数是分开的。

## 仍会重新撞限流的

缓存 key 是 **完整 URL + 全部参数**。下面这些会当成「新请求」：

| 你想做的事 | 会不会重新拉网 |
|---|---|
| 同一币、同一 1h、同一 180 天窗口 | 否 |
| 改成 5 分钟 / 1 分钟再扫一年 | **会**（粒度变了） |
| 把窗口往前再扩、或扫到「此刻之后」的新 K 线 | **会**（`from`/`to` 变了） |
| 第一次没拉过的字段（例如历史盘口、逐笔） | **会** |
| 新上的合约、上次失败没写进缓存的币 | **会** |

另外：缓存的是 **当时那次 API 返回**。Gate 的 `contract_stats` 本身最多回看 180 天，本地不会 magically 变出更早的 OI。

## 实用建议

1. **全量先拉完、别删 `data/cache/`**，这就是以后所有精细回测的原料。  
2. 阈值实验直接在本地重跑评分即可，不必开 Clash、不必租机器。  
3. 若以后经常改区间，最好再存一份对齐后的小时 bar（parquet/csv）。现在是「原始 JSON 缓存 + 每次重拼 bar」，不限流，但重拼 907 个币还是要几分钟。需要的话我可以在拉完后加一层本地 bar 落盘。

一句话：**限流只发生在「第一次见到这个 URL」的时候；数据进盘之后，精细回测是离线的。**
